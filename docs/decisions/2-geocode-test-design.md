# 2 - tests/test_geocode.py 测试设计

## 背景

Week 1 目标：对高德地理编码接口做透——正常 / 异常 / 边界 / 参数化全覆盖。

---

## 测试分层设计

### 正常场景

- 单条用例验证接口基本链路：合法地址 → `status=1` + `geocodes` 非空 + `location` 字段存在
- 不断言具体坐标值，避免高德数据更新导致的误报

### 异常场景

- **空地址**：触发 `INVALID_PARAMS`（infocode=20000），接口参数校验层
- **乱码地址**：触发 `ENGINE_RESPONSE_DATA_ERROR`（infocode=30001），接口引擎处理层
- 两种错误码含义不同，拆成独立用例以区分失败模式

### 边界场景

通过探针实测确认行为后再写断言，而不是假设：

| 输入 | 实测结果 | 断言策略 |
|------|---------|---------|
| 邮政编码（纯数字） | status=1，count=3 | count >= 1（多结果合法） |
| 超长地址（×100） | status=1 | 只断言不报错，不关心结果 |
| 含特殊字符 | status=1，字符被过滤 | status=1 + count >= 1 |
| 纯空格 | status=0，infocode=20000 | 并入参数化错误组 |

### 参数化

- **多城市正常组**（4条）：验证接口对不同地区的普遍支持，而非只对特定城市有效
- **非法输入组**（3条）：验证错误处理的一致性，断言 status=0 即可，不要求相同 infocode

## 放弃的方案

- **断言具体坐标**：坐标精度随高德数据更新可能微变，会产生稳定性差的用例
- **mock 接口返回**：本项目测试目标是真实 API 行为，mock 失去验证意义
- **省份名边界用例**：行为与正常场景差异不大，测试价值低

---

## 关键约束

- `count` 字段为字符串类型，比较前须 `int()` 转换
- 高德用 `status="1"/"0"`（字符串），不是布尔或整数
- `conftest.py` 的 `verify_env` fixture 在 session 级自动执行，确保 Key 缺失时测试整体快速失败
